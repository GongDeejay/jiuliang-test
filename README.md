# 你，几两？| 酒桌绰号

一个趣味「测酒量」H5：8 道题（省份酒窝地图、器皿、年龄群像、圆桌座位、叩指礼、12987、对话、二场电量），答完输入姓氏，生成酒桌绰号（宋三斤、周二两……）。结果有两张图：递给同桌的出示版，和带二维码的朋友圈版。别人扫码先看见你的绰号，测完再并排对照。

**线上地址**：https://jiuliang-test.app.workbuddy.host/?sharecode=W4XEIG3UOR

## 项目结构

```
index.html           # 页面骨架（部署入口，按依赖顺序引用下方脚本）
style.css            # 全部样式（贴纸风、动画、响应式）
data.js              # 题库与文案：8 题选项/吐槽、33 省品牌数据、42 条评语、绰号模板
js/state.js          # 屏幕切换、答题状态、进度点、轻提示
js/layouts.js        # 八种题型的 HTML 版面
js/score.js          # 计分、酒量档位、绰号候选、刻度文案、对照句
js/sharecode.js      # 酒牌短码：编码、校验、拼进二维码链接
js/card.js           # canvas：出示版 + 朋友圈版
js/share.js          # 保存、分享、长按浮层、复制文案
js/result.js         # 结算页
js/surname.js        # 贵姓页与绰号揭晓动画
js/quiz.js           # 出题、点选、反馈、推进到下一题或计分
js/invite.js         # 别人酒牌的落地页
js/boot.js           # 绑定「开始」，有短码就先落地
vendor/qrcode.js     # 二维码生成库（MIT，本地内联，无外部请求）
scripts/verify.sh    # 自动化全流程验证（见下）
scripts/check-sharecode.js
scripts/verify-flow.js
```

改文案/题目/品牌数据只动 `data.js`；改样式动 `style.css`；改交互时按上表进对应的 `js/` 文件。

`js/*.js` 与 `data.js` 一样是无打包的经典脚本，共用页面上的全局绑定（`state`、`idx`、`locked`、`R`，以及 `$`、`show`、`render` 等函数）。`index.html` 里的 `<script>` 顺序就是依赖顺序：`state.js` 先声明状态，`boot.js` 最后绑定「开始」。不要改成 `type="module"`，也不要给单个文件再套一层 IIFE，否则跨文件的函数和状态会断开。

## 本地开发

零依赖，任何静态服务器都能跑：

```bash
python3 -m http.server 8899 --bind 127.0.0.1
# 打开 http://127.0.0.1:8899/index.html
```

用 Cursor / VS Code 直接打开本目录即可编辑 `index.html`。

## 自动化验证（改完代码后必跑）

`scripts/verify.sh` 会先对酒牌短码做往返和篡改检查，再用 playwright-cli 在 375×667 跑：启动页 → 八题 → 贵姓 → 揭晓 → 结算（刻度、分享句、一屏无溢出）→ 出示 / 朋友圈两张图与长按浮层 → 带着短码落地 → 对照 → 最低档不报百分比 → 旧门禁码仍是冷启动、坏码对不上。

```bash
bash scripts/verify.sh
```

验证原则（借鉴 pstack）：**改动不算完成，验证证据才算完成**。任何 UI/逻辑改动，至少跑一遍 verify.sh，确认 8 屏无溢出、流程可走通、出图正常，再考虑上线。

## 刻度怎么来的

结算页和朋友圈图上的「按这套题的刻度，你超过了 X% 的酒友」，X 就是 `js/score.js` 里 `computeCore` 已经在用的 `R.pct`：

```text
pct = round((cap - 12) / 88 * 100)，再夹到 3–99
```

`cap` 是八题选项分的加总。同一个 `pct` 决定七档酒量（三步倒 … 千杯不醉）。没有第二套分数，也不请求接口。这不是全国饮酒普查，产品没有行为后端。最低档（三步倒）不把个位数当笑点：文案改成「今晚你是醒着的那个，这桌靠你收场」，出示版这一档只留绰号。

## 酒牌短码

结果二维码仍回到这个测验。短码版本 1 只装得下：姓（一字或复姓）、酒量档、酒风、绰号序号，后面跟 CRC-16。对不上的参数解不出绰号，也不会拼出半截名字。

线上地址里的 `sharecode=W4XEIG3UOR` 是发布门禁，不是某人的结果。这种解不开的 `sharecode` 会原样留在链接里，真正的结果写在 `from`。已经发出去、只带门禁码的图，扫开仍是冷启动。本地没有门禁码时，结果直接写进 `sharecode`。

带有效结果打开时，先看到「宋测出了「宋一斤」」和酒风色块，点「轮到你了」再答题。测完把两个绰号和酒风并排，加一句按两人酒量词写的桌边话（例如「一斤对一口，一口那位今晚负责醒着」）。分享文案可以是「我是宋一斤，你几两？」，不分享也能看结果。

朋友圈图上的那一句来自座位、二场、对话、器皿或家乡，按酒风挑一句。第一次断片的年纪默认不写，可以自己点上，也可以把任何一句拿掉。

## 浏览器测试注意事项

- playwright-cli 不支持 `file://` 协议，必须走 http 服务器；
- headless Chromium 沙箱失败时，用配置 `.playwright/cli.config.json`（`--no-sandbox`）+ 非沙箱终端运行；
- headless 环境里 `navigator.share` 可能永远挂起，代码中已有 1.6s 超时兜底，验证分享逻辑时注意这一行为差异。
